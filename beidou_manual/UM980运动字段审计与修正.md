# UM980 速度与轨迹字段审计（2026-10-28）

## 范围和依据

本次检查 `gnss_kinematic_hmi.py` 的产品分发、`gps_kinematic_analyzer_beidou.py` 的报文恢复、BESTNAV字段解析、速度统计/作图、位置到ENU转换、异常点选项，以及三份北斗原始日志和报告。北云、华测由各自独立分析器处理，本次不据北斗手册修改它们。

厂家依据为同目录 `Unicore Reference Commands Manual For N4 High Precision Products_V2_CH_R1.15.pdf`：

- 表7-70，BESTNAV：PDF第223–225页，印刷190–192页。
- 表7-51，ASCII消息头：PDF第184页，印刷151页。
- GGA表7-4，海拔与undulation正负号：PDF第116–117页，印刷83–84页。

报告中的速度为接收机输出或其分量的数学变换，未用外业真值验证测速误差。位置差分的异常点阈值属于现有软件功能的用户设置，不是厂家质量判据。

## 确认的问题与修正

### 1. 速度字段错位两项

分号后按零基下标计数；手册ID等于下标加2：

| 下标 | 手册字段 | 单位/含义 | 修正前误用 |
|---:|---|---|---|
| 21 | V-sol status | 速度解状态 | 映射正确 |
| 22 | vel type | 速度类型 | 映射正确 |
| 23 | latency | 速度延迟，s | 当作水平速度 |
| 24 | diff_age | 速度差分龄期，s | 当作航迹角 |
| 25 | hor spd | 对地水平速度，m/s | 当作垂直速度 |
| 26 | trk gnd | 相对真北的对地运动方向，deg | 当作垂直速度标准差 |
| 27 | vert spd | 垂直速度，m/s，向上为正 | 当作水平速度标准差 |
| 28 | Verspd std | 垂直速度标准差，m/s | 未正确取用 |
| 29 | Horspd std | 水平速度标准差，m/s | 未正确取用 |

三份日志的latency和速度diff_age均为0。原代码因此将水平速度算成0，东/北分量也全为0；真实水平速度被画在Up方向。三维速度统计随之错误。

修正为 `E=hor_spd*sin(trk_gnd)`、`N=hor_spd*cos(trk_gnd)`、`U=vert_spd`（三角函数前转换弧度）。三维速率为 `hypot(hor_spd,vert_spd)`。报告分别给出水平速度和三维合速度，不再混用名称。均值是有效历元算术平均，不是路程/总时长。

### 2. 未使用速度latency校正时刻

表7-70明确要求用历元时间减去latency。现单独保存 `velocity_latency`、`velocity_diff_age`，绘图使用 `velocity_timestamp=timestamp-latency`。位置diff_age仍取f[11]，速度diff_age取f[24]，两者不参与速度分量计算。

当前三份日志latency全为0，因此此改动不平移本批速度曲线。异常输入缺少latency时不推算延迟：有效速度数值仍计入统计，该点的校正时间序列留空，并报告数量。

### 3. ENU将海拔高误作椭球高

表7-70定义f[4] hgt为海拔高、f[5] undulation为大地水准面与WGS84椭球面的差距。GGA定义大地水准面高于椭球面时undulation为正。原ECEF公式要求椭球高，但直接传入hgt。

现在保留海拔高用于高度时间序列，另计算 `ellipsoid_height=hgt+undulation` 用于WGS84 ECEF→ENU。缺少undulation或坐标系不是WGS84时不生成该点的ENU坐标。

本修正只改变ENU所需的高程语义和输入值；没有把GGA海拔字段反向当作BESTNAV字段，也没有用未定义的模型补齐undulation。平面图变化可能很小，但原高程语义仍必须按手册处理。

### 4. 时间忽略GPS周数；采样缺槽估计少计端点

ASCII头原先只取周内毫秒/1000。现所有ASCII专有报文时间路径统一使用 `week*604800+ms/1000`，与已有OBSVM连续时间口径一致。GPS正常跨周时不会把次周0秒排到前面。

采样期望历元数改为 `跨度/实测周期+1`。例如时间0、1、2、4秒四个历元，应有5个槽位、缺1个，即20%；旧式少计一个端点后会算为0%。半边天实测670帧、跨度670秒，期望671帧，修正丢帧估计约0.149%。

本批三份日志均为GPS周2441；跨周通过合成边界用例验证。接收机时间重置/UNKNOWN时刻重建未在此修改中推断或实现。

复核发现ASCII头TimeStatus也必须参与时间有效性判断。表7-51列出Unknown/Fine，并说明Unknown时接收机还不能计算准确GPS时间。现在仅将手册明确的FINE状态用于采样率、速度/位置时间序列和位置差分速度；UNKNOWN或未识别状态保留位置/速度数值，但不用于时间差，也不用于校正速度曲线时刻。没有按相邻点或报文顺序猜测UNKNOWN时刻。三份实际日志的BESTNAVA时间状态均为FINE，因此此处理不改变本批速度数值。

### 5. 缺失速度被默认成零、无解位置被跨段连线

原速度解析将空字段填0；现在缺失、非法或非有限数保留为NaN，失效速度不进入统计且图中断线。位置与速度分别按各自状态判断；城市有4个位置状态INSUFFICIENT_OBS/NONE的历元，速度仍为SOL_COMPUTED/DOPPLER_VELOCITY，保留其速度。

位置时间序列和ENU图不跨显式无解记录连线；UNKNOWN时间状态的点不进入位置时间序列。位置有效性增加有限坐标检查。原先对(0,0)的无依据剔除已移除：零纬零经在坐标数值上有效，是否有位置解由手册定义的p-sol status判断。

### 6. 异常点开关原来没有执行逻辑

GUI/CLI原先接收mark_anomalies和speed_threshold，却未在轨迹中使用。现沿用项目已有平面轨迹标记口径：相邻有效记录的 `hypot(ΔE,ΔN)/Δt` 超过用户阈值时在后一点画红X；不跨无解记录，不对重复/倒退时间虚构dt。阈值必须是有限正数，默认关闭。

此功能仅提示用户阈值超限，不据此认定接收机故障，不替代BESTNAV多普勒速度。默认重生成的三份报告保持未勾选状态。

## 路程与未发现错位的部分

北斗分析器没有累计路程/里程指标，也没有速度积分求路程。因此不存在可据本批数据修正的累计路程值，报告现明确说明未计算累计路程。

检查的BESTNAV位置状态、位置类型、纬经度、位置σ、基站ID、位置diff_age/sol_age和跟踪/解算卫星数字段索引与表7-70一致。原E/N分解公式方向正确，问题在上游字段错位。报告ENU坐标是相对首点的轨迹，不是测量真值误差。
