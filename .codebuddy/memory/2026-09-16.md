### check_message_integrity() 判定规则
- 报文缺失 → error（红）
- 实际周期与设定偏差 >5% → warn（橙，🟠周期不符）
- 估算丢帧率 >1% → warn（橙）
- 正常 → ok（绿，🟢正常）
- RELAXED_PERIOD_NOTES 表中的项 → info（黄，🟡提示）：实测比设定输出更密不算异常
  （北云 BESTPOSA 设定1.0s实测0.2s、GPGGA 设定1.0s实测0.2s 均属此类）

### ⚠️ 华测 #BESTVA 字段映射（经交叉验证，勿再改回 BESTVEL 布局）
#BESTVA 数据字段（手册3-47，实测10字段）：
  [0]速度解状态 [1]速度类型 [2]Reserved [3]水平对地速度m/s
  [4]对地航迹角(度,真北) [5]垂直速度m/s [6]latency延迟s [7]差分龄期s [8]Reserved
分解: vel_n=hor_spd*cos(trk_gnd), vel_e=hor_spd*sin(trk_gnd), vel_u=vert_spd
验证依据: TOW272300-272900 步行时段 BESTPA 位移速度≈0.8-1.1m/s 与 [3]字段(0.003-0.93)吻合；
  [4]字段取值0-360连续变化符合航迹角。初版误按 BESTVEL 布局导致 176m/s 异常，已修正。
仅取 速度解状态==SOL_COMPUTED 的有效帧。

### 华测两种数据格式
- **新采集格式**（如 20260916113643_M720_COM11.log，78MB）：标准 ASCII `#BESTPA/#BESTVA/#RTKPA/#RTKVA`
  - GMF 头 [6]=GPS周 [7]=TOW**毫秒**（/1000 得秒）；数据字段同 BESTP，末字段=基站ID
  - parse_bestpa_ascii() / parse_bestva_ascii() 解析；get_velocity_data() 优先 <RTKV 回退 #BESTVA
  - parse_bestgnss_posa/parse_bestposa/analyze_rtk_link/卫星可见性 在缩写源空时回退 #BESTPA
- **旧采集格式**（如 20260915162214_COM11.log，596KB）：缩写 `<BESTP/<RTKP/<RTKV`（两行结构，高丢帧）

### 头字段差异（勿混用）
- 北云头 [6]=周秒（单位秒）
- 华测 GMF 头 [6]=GPS周，[7]=TOW（单位毫秒，需/1000）

### 工程注意事项（Windows/PowerShell 踩坑）
- PowerShell 不支持 heredoc：多行Python用 `@'"'"'...'"'"'@ | Set-Content -Encoding UTF8 _x.py; python _x.py; Remove-Item _x.py`
- 改源码用 Python 脚本 + assert old in s 防静默失败；改完跑 ast.parse 语法检查
- 读 .py 用 utf-8-sig（防BOM），写 .py 用 utf-8（无BOM）；写 README/报告用 Set-Content -Encoding UTF8
- 控制台GBK：读报告/源码里的中文会显示乱码，用 python -X utf8 -c "io.open(...,encoding=utf-8)" 验证真实内容
- 大文件分析耗时：86MB北云约100s、78MB华测约500s（绘图慢），后台运行需等 exit=0
