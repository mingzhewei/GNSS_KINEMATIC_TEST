## 二、手册字段核实（不猜测，逐项查原文）

### 北云 UG016
- `BESTGNSSPOSA` 4.2.2：
  - 数据字段[7]/[8]/[9] = Lat σ / Lon σ / Hgt σ
  - 手册字段9/10/11，二进制偏移 H+40/H+44/H+48，Float4。
  - 数据[13]=#SVs 跟踪卫星数，[14]=#solnSVs 参与解算卫星数。
- `$GPGST` 4.1.7：
  - 数据字段[2] = “用于导航计算的伪距标准偏差的平方根值”，即伪距残差RMS。
  - 数据[3]/[4]=椭圆长/短半轴σ(m)，[5]=长轴方位(°)，[6]/[7]/[8]=纬度/经度/高度σ(m)。
  - GST只有UTC时间，无GPS周秒；不与BESTGNSSPOSA周秒强行合并时间轴。
- `INSPVAXA` 4.2.15：
  - 数据[6]/[7]/[8]=N/E/U速度(m/s)
  - [9]/[10]/[11]=roll/pitch/azimuth
  - [12]/[13]/[14]=lat/lon/hgt σ
  - [18]/[19]/[20]=roll/pitch/azimuth σ
- `TRACKSTATA` 4.2.26：
  - 每通道10字段，通道内相对偏移+5为C/No(dB-Hz)。

### 华测 M7 V2.7
- `BESTP/#BESTPA` 表3-38：
  - 数据字段[8]/[9]/[10] = lat/lon/hgt σ，单位m。
  - 手册字段10/11/12，二进制偏移 H+32/H+36/H+40，Float4。
  - 数据[13]=#SVs，[14]=#solnSVs。
- `$GNGST` 3.1.5 表3-9：
  - 数据字段[2] = rms，“伪距、DGNSS修正值的标准偏差的均方根”，即伪距残差RMS。
  - 数据[3]/[4]=误差椭圆长/短半轴σ(m)，[5]=长轴方位(°)，[6]/[7]/[8]=lat/lon/hgt σ(m)。
- `#BESTDOPSA` 表3-36：
  - [0]PDOP、[1]GDOP、[2]HDOP、[3]TDOP、[4]HTDOP；无VDOP。
- `$GNGSA` 表3-3：
  - [15]PDOP、[16]HDOP、[17]VDOP；VDOP唯一来源。

### 统一口径
- 位置σ：北云 `BESTGNSSPOSA` 数据[7]/[8]/[9]；华测 `<BESTP/#BESTPA` 数据[8]/[9]/[10]。
- 伪距残差RMS：北云 `$GPGST` 数据[2]；华测 `$GNGST` 数据[2]。
- 只统计 `SOL_COMPUTED` 且坐标有效历元。
- GST只接受RMS非空的合法报文，不插值、不猜测。
- 图顺序统一：latσ、lonσ、hgtσ、RMS。
- 单位统一m。
- 报告明确σ为接收机自估精度，不是外业真值误差。
- 位置σ横轴用GPS周秒相对时间；RMS横轴用GST UTC相对时间，两轴分开标注，不强行对齐。

## 五、整体审计结论

### 已核实正确
- 位置σ字段映射：两边均正确。
- GST字段映射：两边均正确。
- 速度：两边均为N/E/U三分量，单位m/s。
- 卫星数：两边均区分Tracked(#SVs)与Used(#solnSVs)。
- DOP：两边字段来源和手册一致。
- C/N0：两边单位dB-Hz，阈值口径一致。
- 位置σ/RMS四联图：顺序、单位、版式一致。
- 报告图片引用全部存在，无死链。

### 发现的问题
1. 华测位置时间序列仍先过滤无效坐标，导致时间轴压缩；北云已修为真实时间轴+NaN断线。两边口径不一致，待修。
2. 华测 `_plot_position_time_series` 存在 `source='ins'` 和 `position_time_series_ins.png` 残留死代码；华测为纯GNSS，不应保留INS分支。
3. 华测ENU图轴标签为 `Easting/Northing`，北云为 `East/North`，建议统一。
4. 北云ENU用equirectangular近似，华测用WGS84 ECEF→ENU严格转换；短距离差异小，但属算法口径差异，报告应披露。
5. 华测DOP图中VDOP来自无时间戳GSA组合条，用序列比例映射到BESTDOPSA时间轴；应明确这是比例对齐，不是时间戳对齐。
6. 华测MD报告缺少GNSS解类型分布、C/N0、解算状态图的Markdown图片引用；HTML有，MD没有，属报告格式差异。
7. 北云README中BESTPA表述可改为华测`#BESTPA`，当前上下文无歧义。

## 六、统一 HMI：gnss_kinematic_hmi.py

### 功能
- 产品注册表 `PRODUCTS`
- 当前注册：
  - `beiyun`: `gps_kinematic_analyzer_beiyun.py`
  - `huace`: `gps_kinematic_analyzer_huace.py`
- 多文件选择
- 分析队列
- 后台线程依次调用产品脚本
- 实时显示子进程日志
- 成功后自动打开 `report.html`
- 可选自动打开输出目录
- 支持手动打开选中报告/目录
- 以后新产品只需在 `PRODUCTS` 里追加 `ProductConfig`

### 关键实现
- 开发模式：`python.exe` 调产品脚本。
- EXE模式：`GNSS_Kinematic_HMI.exe --worker <product_key> <input_file>` 调自身作为worker。
- worker从 `sys._MEIPASS` 读取内嵌产品脚本。
- 修复Tkinter跨线程访问问题：进入后台线程前先读取 `open_report_var` / `open_dir_var`。
- UI队列线程安全更新状态和日志。

```bash
python -X utf8 -m PyInstaller --noconfirm --clean GNSS_Kinematic_HMI.spec
```

如需固定为 `Build\GNSS_Kinematic_HMI`，将 `dist\GNSS_Kinematic_HMI` 复制过去。

- 本次记录时已重新执行打包，`dist\GNSS_Kinematic_HMI` 已生成；如根目录没有 `Build`，从 `dist` 复制即可。
