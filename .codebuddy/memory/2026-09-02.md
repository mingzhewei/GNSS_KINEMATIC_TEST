# 2026-09-02

## 项目代码通读与理解（为适配新GPS模组做准备）

用户要求通读 GPS 动态分析项目，后续将引入新的 GPS 模组（指令/数据格式不同），希望用类似框架做相同分析。

### 项目核心理解
- 主程序 `gps_dynamic_analyzer.py`（~2450行，v2.0），针对北云科技 UG016 协议（组合导航 RTK+INS 接收机）的动态数据离线分析工具
- 数据格式两类：NovAtel风格 ASCII（#开头，头部含GPS周/GPS周内秒，分号后为数据字段，*后为CRC32，程序未校验CRC）；NMEA 0183（$开头）
- 核心报文：#INSPVAXA(100Hz INS组合导航:位置/速度/姿态/精度)、#RAWIMUA(100Hz原始IMU,未解析)、#BESTGNSSPOSA(2Hz纯GNSS位置)、#BESTPOSA(1Hz解算状态)、#HEADINGA、$GPGGA(卫星数/HDOP来源)、GSA/GSV系列
- 流程：parse_dat_file按报文头分类 → save_header_files分类保存 → 各parse_*解析(带缓存) → analyze_*统计(采样率/解类型/卫星/DOP/速度) → generate_plots(11张图,matplotlib) → 生成HTML+MD报告
- ENU转换：_latlon_to_enu()，WGS84→ECEF→ENU，以首点为参考点
- 入口：CLI(argparse) + Tkinter GUI；异常点检测：速度阈值法可选标记
- 输出：与数据文件同名目录，含report.html/report.md/11张png/各报文.dat

### 发现的问题（已与用户交流）
1. 解析层（北云专有）与通用分析层（ENU/统计/绘图/报告）耦合在一个大类中，换模组需解耦
2. INSPVAXA采样率估算硬编码 `5.0 * ratio`（假设GPGGA 5Hz，实测数据是2Hz，会算错）
3. HTML报告章节编号重复（两个"4."）；position_time_series.png 引用错误（实际文件名是 position_time_series_gnss.png，图裂）
4. RAWIMUA/HEADINGA/GSA/GSV 仅分类保存未解析
5. GUI 分析同步阻塞，status_label 从不更新
6. analyze_position_accuracy() 空壳（动态无真值）
7. gps_dynamic_analyzer_backup.py 为旧版备份

### 适配新模组的方案思路
- 分层重构：数据源适配层（报文识别+字段解析+解类型枚举映射，每模组一个实现）+ 通用分析层（统计/ENU/绘图/报告，接收统一数据模型）+ 前端（CLI/GUI）
- 统一数据模型：以"历元"为单位{timestamp, lat, lon, hgt, solution_type(枚举), lat/lon/hgt_sigma, vel_n/e/u, roll/pitch/azimuth, num_sats, hdop}
