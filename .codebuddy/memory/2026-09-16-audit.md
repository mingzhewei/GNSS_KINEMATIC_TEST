# 2026-09-16 补充：报告审计 + 组合惯导/纯GNSS 分立体系 + 特色字段

## 一、报告审计结论（是否符合行业共识）

### 字段用法（基本符合共识）
- 北云 BESTGNSSPOSA 作主源（符合 NovAtel 系惯例）；INSPVAXA 是组合惯导正确字段；
  华测 #BESTPA 主源、#BESTDOPSA DOP、GGA/GSA/GSV 辅助，均符合共识。
- 移动站专用（moved/cv_sats/diff_pos 基站字段不使用），符合 rover-only 设定。

### 发现的问题（需在报告中诚实标注）
1. **"水平定位精度 0.0000米-满足厘米级"是误导占位**：Kinematic 无真值，
   analyze_position_accuracy 是空壳(horizontal_accuracy 恒 0)，不应显示为"通过"。
   建议改为显示 INSPVAX/BESTP 自带的 σ(标准差)作为精度指标（接收机自估，非真值比对）。
2. **固定解率阈值(95/80)**：行业**无强制统一标准**，是工程经验口径，报告已标注。
3. **Kinematic 缺核心动态专项**：当前只有速度曲线。行业看动态性能主要看
   ①遮挡/多路径下固定保持与重捕获(re-fix)时间 ②RTK中断后INS桥接漂移 ③姿态动态(仅组合惯导)。
   需要"重复路过已知点"或真值参考才能量化误差，当前只能定性展示。

## 二、组合惯导 vs 纯GNSS 两套报告体系（用户拍板方向）
- **同一套核心逻辑**（统计/绘图/报告结构/评估口径），设备差异仅在"字段映射层"。
- 北云(组合惯导)：BESTGNSSPOSA(GNSS) + INSPVAXA(INS位置/速度/姿态/σ)。
- 华测(纯GNSS)：#BESTPA(位置) + #BESTVA/#RTKV(速度)。无惯导。
- 评估逻辑统一收敛到 `kinematic_core/criteria.py`（两版共用同一套阈值函数）。

## 三、新建 kinematic_core 包（统一评估引擎）
- `kinematic_core/criteria.py`：Metric 类 + 统一阈值函数
  eval_fix_ratio / eval_sat_count / eval_hdop / eval_diff_age /
  eval_env_status(华测) / eval_ins_sigma(北云)。
- 每个 Metric 含 note(测什么/怎么算好/怎么算坏) + basis(依据: 手册章节/行业共识/工程经验)。
- **阈值诚实性**：RTK固定解率、卫星数、差分龄期等无强制标准→标注"工程经验值"；
  华测 ENVSTATUS 阈值(85优秀/60-84一般/<60不合格, SNR>=38开阔/32-37半遮挡/<=31严重,
  PDOP<=2.5好)直接来自 M7 手册表3-51/3-52。

## 四、特色字段落地（已端到端验证）
- **北云组合惯导特色**(INSPVAXA)：载体姿态(横滚/俯仰/航向) + 位置σ + 航向σ。
  parse_inspvaxa 补提取 roll_sigma/pitch_sigma/azimuth_sigma。
  analyze_special_metrics() → analyze_ins_sigma()。
  com3.dat 实测：位置σ 0.056m(分米级-警告), 航向σ 0.328°(一般-警告)。
- **华测纯GNSS特色**(ENVSTATUSA)：环境质量分/平均SNR/卫星可视比率/电离层活跃。
  新增 parse_envstatus() + analyze_special_metrics()。
  20260916113643 实测：环境分69(一般-警告), SNR 38(开阔), 可视率80%, 电离层WEAK。
- 两版 HTML+MD 报告新增「特色指标(设备专有字段)」带注释表格区块。

## 五、工程踩坑（重要）
- 补丁替换 `from collections import defaultdict, Counter` 时，若只匹配 `defaultdict`
  会把 Counter 误并入新导入行 → NameError。务必匹配完整行并保留 Counter。
- 华测完整跑 78MB 数据约 8-9 分钟（绘图慢），后台需耐心等待 exit=0。
